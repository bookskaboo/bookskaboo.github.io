## Sound test factory

The fresh [factory with ambient music](../../outputs/action-sounds/factory-with-music.html) embeds the selected string-only loop alongside all piano action cues. Click Enable sound: music starts at 15%, effects at 30%. Adjust them separately, uncheck Ambient music to compare effects alone, or use Mute for both. Music is a separate looping Web Audio source, so research/upgrade/victory cues and factory reset do not cut or restart it. Hidden tabs suspend the shared audio clock and resume from the same music position. Game pause leaves music playing. No setting is persisted and no campaign audio hook is added. `npm run preview:sound-game` now rebuilds action sounds and ambient music before embedding both into the standalone file. [Focused tests and browser evidence](../../outputs/action-sounds/factory-music-verification.json) are retained.

Open the [standalone test factory](../../outputs/action-sounds/playground.html), or use `http://127.0.0.1:4174/outputs/action-sounds/playground.html` with the local server running. Rebuild it with `npm run preview:sound-game`, which refreshes the audio pack first. The source entry is [playground.html](playground.html), with [React controls](playground.tsx), [fixture](fixture.ts), [event detection](events.ts), [preview mixer](audio.ts) and [styles](playground.css).

This is an isolated supplied fixture using the real GameEngine, PixiPlayfield, Build menu, Upgrades, Node Map and recipe panels. It does not import App or its campaign engine. Autosave is disabled, snapshots remain in memory, Node Map layout persistence is disabled, and recipe views use the explicit nonpersistent option. Ordinary game recipe panels retain their saved preference by default. Reload/reset discards the test factory. No campaign save is read or written.

Routine production, packets, camera motion and waiting remain silent. The mixer enforces shared rejection cooldowns, four concurrent sources, milestone priority and one milestone at a time. It uses the current generated WAV data embedded into the standalone bundle, without network audio requests.

The focused engine tests cover successful/no-op actions, batch side effects, normal Core payments, upgrade cue priority, navigation and storage isolation. The shared recipe-view tests cover the preview opt-out and normal-game default. ## Sample-pack verification

File checks cover WAV headers, durations, clipping headroom, silent endpoints, asset hashes, deterministic rebuilding and sheet-to-asset references. Browser checks cover explicit playback, switching samples, reel labels, Stop, volume, Mute and viewport/focus behavior. Current piano checks are recorded in [piano-verification.json](../../outputs/action-sounds/piano-verification.json). Initial mixed-palette observations remain separate historical evidence.

Technical metrics and successful browser playback do not establish subjective sound quality, listening comfort, hardware loudness or long-session fatigue. The user should listen on their normal setup before adopting the palette. The pack and test factory do not integrate sound into the campaign App, persist audio preferences, measure normal-play balance or publish a game release.
