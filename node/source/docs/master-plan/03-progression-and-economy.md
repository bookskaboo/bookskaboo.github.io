# Progression and economy design

## Existing constraints

**Timing prerequisite (Q26A, November 2, 2026), implemented locally:** start Research Center consumption at five seconds per synchronized Core set. Keep the existing six speed-research ranks, yielding 4.5, 4, 3.5, 3, 2.5 and 2 seconds. Use the corrected baseline before further calculations; refreshed live analysis is current, while older experimental timing and throughput reports require revalidation. This changes research timing, not Core recipes or prices. Existing elapsed-time targets remain hypotheses.

Paid research consumes equal quantities of every required Core type through its highest tier. New Core access uses available preceding tiers. Core recipes do not consume other Cores, including indirectly. Earlier Core factories therefore remain relevant without turning higher Cores into nested Core bills.

Capability unlocks remain affordable; efficiency and convenience are optional investments. Nine machine families have six efficiency ranks, with rank r costing 10r of each Core through tier r and reducing cycle time to (100 − 10r)% of base. **Deferred:** changing efficiency costs or effects. Keep the current system.

## Waste introduction at Complex

**Agreed direction (Q32, November 2, 2026):** introduce waste with Complex Cores instead of Shiny Cores. Shiny production should not generate waste or require waste handling. Complex-tier production becomes the first waste-management challenge; this is a progression-design change, not yet a runtime recipe change.

The shared Pure Mythril recipe currently produces two Slag alongside two Pure Mythril. Remove that pre-Complex waste output in the intended design; do not re-enable it on the shared Shiny supply when Complex research completes. Current Complex intermediates already have probabilistic Fines, Flux and Crust outputs. Q32A adopts a guaranteed waste byproduct from at least one recipe. Exact source recipe, material, quantity and any additional probabilities remain open.

Align waste buffers, transport, basic handling/recovery and optional teaching with the chosen Complex-stage introduction. Necessary handling must be available before the first waste-producing batch, without a self-gating first-Core requirement. Review early Mythril/Sorting Station discovery unlocks so they do not present waste as a Shiny requirement. Keep rare waste out of mandatory progression ingredients. Existing standard input quantities, primary yields and cycle times remain the comparison baseline until a specific recipe change is reviewed.

**Shared product/waste outlet (Q53, November 2, 2026):** the user requires waste to leave through the same connection port as the desired product, creating a mixed stream that players must filter. Apply this to waste-producing production recipes, including the mandatory Controller stream and both alternative sets. This replaces automatic separation at a dedicated machine waste port. Typed downstream inputs, branching and item-choice routing must not silently extract only useful products and bypass the intended filtering task. Exact stream ordering, capacity, blocking and filter behavior still need specification. All batch outputs must be preserved; required separation must be usable before the first Controller batch, without paying Complex Cores for initial access. Waste Bin/Link and recovery remain useful after separation. This is adopted design; runtime still has separate product/WASTE ports.
