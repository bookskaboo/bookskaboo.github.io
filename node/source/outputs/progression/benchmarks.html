Refinement to the pacing model

  • Use required remaining sets / bottleneck delivered sets per second, bounded by lab capacity. With ready buffer B, supply bound is max(0,Q-B)/R; research still takes Q lab ticks. Do not add overlapping production and lab time.
  • Forced wait = max(0, unlock completion time - time useful work runs out), with prerequisites and queue occupation included in the full event model.
  • Budget the complete mandatory unlock path, not each cheap project in isolation. Let upgrade work run on established lower-tier supply; avoid mandatory optional-upgrade gates.
  • Capability research should be available to select when needed. In a single-lab game, queued optional upgrades can delay unlocks unless switching preserves contributions. Automatic priority is a proposal, not implemented here.
  • Use 2/5/10 minute useful-work windows as sensitivity inputs only. Set final limits using earliest reasonable readiness in playtests.
  • Introduce one primary unfamiliar logistics rule at a time, then combine familiar rules. This is a proposed design heuristic, not a measured rule from either reference game.
